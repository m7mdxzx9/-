# تطبيق جوال طلاب الذكاء الاصطناعي — جامعة أم القرى

تطبيق **Expo + React Native** (TypeScript) لطلاب بكالوريوس الذكاء الاصطناعي: متابعة دراسية حقيقية
بحساب المعدل، خريطة تسجّل الخطوط التي تمرّ بها، ومحتوى قابل للتحديث من لوحة تحكم.

> كان المشروع في نسخته الأولى موقعاً ثابتاً (`src/index.html`)، وقد حُذف وتحوّل إلى تطبيق جوال.
> بيانات الخطة التي كانت في الموقع استُخرجت إلى `content/*.json` ليقرأها التطبيق والسيرفر معاً.

## التشغيل

```bash
npm install
npm run web        # معاينة في المتصفح على http://localhost:8081
npm run android    # على جوال/محاكي (يتطلب Expo Go أو dev build)
npm run ios        # macOS فقط
npm run typecheck  # فحص الأنواع
```

### السيرفر ولوحة التحكم

```bash
npm run server                      # http://localhost:8787  +  /admin
ADMIN_TOKEN=سرّي npm run server     # تغيير رمز الحفظ
npm run content:push                # content/ → السيرفر
npm run content:pull                # السيرفر → content/ (بعد تعديلات اللوحة)
```

من التطبيق: الإعدادات → اكتب `http://localhost:8787` (أو IP جهازك على الجوال) → اختبار الاتصال →
مزامنة المحتوى. بدون سيرفر يعمل التطبيق كاملاً من `content/*.json` المضمّنة.

## هيكلة المشروع

```
app.json                     إعدادات Expo (اسم، أيقونات، expo-location، RTL)
content/*.json               الخطة والبرنامج والمسارات والمشاريع والمصادر (المصدر المضمّن)
server/index.js              سيرفر Node بدون تبعيات: /api/content + /api/devices + /admin
server/public/admin.html     لوحة التحكم
scripts/sync-content.js      رفع/سحب ملفات المحتوى
src/app/                     الشاشات: index, plan, map, explore, settings
src/components/map/          غلاف الخريطة (iframe للويب / WebView للجوال) + بروتوكول الرسائل
src/lib/                     app-state (Context), content, progress, gpa, geo, watch(.web), storage, mapHtml, types
src/ui/kit.tsx               عناصر الواجهة: Card, Chip, Btn, Segmented, Bar, Notice, Sheet, MiniTrack
src/constants/theme.ts       الألوان فاتح/داكن + حالات المادة
```

### تدفق البيانات

```
content/*.json  ──تُقرأ──►  src/lib/content.ts  ──►  AppProvider (src/lib/app-state.tsx)
                                    ▲                          │
        /api/content (لوحة التحكم) ─┘   مزامنة/كاش AsyncStorage ▼
                                       الشاشات + src/lib/gpa.ts (MGA/SGPA/تنبيهات)
تقدّمك ومساراتك ──► AsyncStorage (محلي أولاً) ──اختيارياً──► /api/devices/<deviceId>
```

## النشر على GitHub Pages

نعم — نسخة الويب تُصدَّر كموقع ثابت (`expo export -p web`) وتُخدم من Pages بلا أي سيرفر.
البناء مُختبَر: ٧ مسارات ثابتة (`/`, `/plan`, `/map`, `/explore`, `/settings`, …) مع أصول تحت مسار الأساس.

```bash
EXPO_BASE_URL=/اسم-المستودع npm run pages:build   # يبني إلى dist/ ثم يجهّزه للنشر
mkdir -p /tmp/site/- && cp -r dist/* /tmp/site/-/ # محاكاة الاستضافة: الموقع تحت /-/
python3 -m http.server -d /tmp/site 8090          # ثم افتح http://localhost:8090/-/
```

**التلقائي:** `.github/workflows/deploy-web.yml` يعمل عند كل push على `main`:
`npm ci` → `typecheck` → بناء → `scripts/pages-prepare.js` → نشر على Pages.
`EXPO_BASE_URL` فيه مشتق من اسم المستودع تلقائياً (ولهذا المستودع `اسمه = -` فيصبح `/ -` → `/-`).

**مهم — قيدان على Pages:**
1. `server/index.js` لا يعمل هناك (Pages ملفات ثابتة فقط). لوحة التحكم تُشغَّل محلياً، ثم
   `npm run content:pull` → commit → الـ workflow يعيد البناء. المزامنة من داخل التطبيق تفشل بهدوء
   وتبقى على المحتوى المضمّن (offline-first).
2. ما يشتغل في المتصفح: المتابعة وGPA والتخزين المحلي، وتسجيل المسارات (Pages يعطيك **HTTPS**
   فيقبل المتصفح إذن الموقع)، وبلاط OpenStreetMap. ما لا يشتغل: رفع نسخة للسيرفر ومزامنة المحتوى.

**نصيحة عن الرابط:** مستودع باسم `-` يعطي `https://USERNAME.github.io/-/` — يشتغل، لكن إن أردت
رابطاً أنظف انشر على مستودع `USERNAME.github.io` أو نطاق خاص، وعيّن `EXPO_BASE_URL=''` (عندها
يُسقط `app.config.js` مسار الأساس من تلقاء نفسه).

## ما تم التحقق منه فعلاً

- `npm run typecheck` صفر أخطاء، و Metro يبني حزمة الويب (٩٠٥ وحدة) بلا تحذيرات.
- الشاشات الخمس تُرجَع `200` وتحتوي نصها العربي عند التشغيل بوضع `static` (SSR).
- السيرفر: `GET /api/content` يُعيد ٣٢ مقرراً و٨٨ ساعة؛ `PUT` بدون توكن `401`؛ JSON مكسور `400`؛
  متطلب غير موجود `400`؛ `scripts/sync-content.js --push` نجح للملفات الخمسة؛ دورة `/api/devices` كاملة.

## ما لم أختبره (لا تعرفه إلا عندك)

- **التشغيل الأصلي (Android/iOS)**: لا يوجد محاكي هنا. المنطق مشترك، لكن `react-native-webview`
  و`expo-location` لم يُجرَّبا على جهاز. أي خطأ يظهر عند `npm run android` غالباً منهجه فقط.
- **بلاط الخريطة**: يُجلب من `tile.openstreetmap.org` من متصفح/جهاز المستخدم. بلا إنترنت تبقى
  الخطوط ظاهرة في العرض المبسّط أو كطبقة متجهات.
- **الإذن بالموقع داخل معاينة المتصفح**: قد يحجب المتصفح `geolocation` داخل iframe → استخدم
  «وضع المحاكاة» أو «مسار تجريبي» لتجربة الحفظ والرسم.
- **بناء APK**: `npm run build:apk` يحتاج `eas-cli` وحساب Expo (`npx expo install eas-cli`)،
  ولم يُجرَّب هنا.

## ملاحظات صريحة

- الخطة في `content/courses.json` **توضيحية** (٣٢ مقرراً/٨ فصول) مبنية على محتوى المنصة السابقة،
  وغير معتمدة رسمياً. عدّلها من اللوحة أو الملف ثم `npm run content:push`.
- مقاييس التقديرات في `content/program.json` تحتاج مطابقة مع لائحة كليتك.
- المساعد الذكي يفتح ChatGPT بموجه جاهز — لا يوجد مفتاح API ولا إرسال بياناتك لأي مكان.
- `lang` في صفحة الويب يثبت `ar/rtl` وقت التشغيل بعد التحميل، لأن قالب Expo الثابت يكتب `en`.

## Flutter

النسخة المطلوبة ثانياً (Flutter) غير قابلة للتجربة في هذه البيئة لأن حزم Flutter تُنزَّل من
`storage.googleapis.com` وهو محجوب. التطبيق الحالي بـ Expo يعطيك نفس المنطق ويُبنى لأندرويد و iOS،
فإن أصررت على Flutter أستطيع كتابة مشروع `flutter/` من نفس الشاشات والمنطق — لكن سيكون كوداً
غير مُختبَر.
